# StudyPilot Desk 桌面动效系统设计

## 目标

建立一套克制、精确、有层级且可维护的桌面动效系统，让课程、知识笔记与画布之间具备可感知的空间连续性，同时保证浅色/深色主题、键盘操作、`prefers-reduced-motion` 与 Electron 渲染性能一致可靠。

## 设计原则

1. **运动解释结构**：进入更深层级时内容向前推进，返回时反向退出，同层模块只做短距离横向交接。
2. **共享元素建立连续性**：课程封面进入课程主页、知识笔记封面进入画布时使用稳定的 View Transition 名称；不支持原生 API 时退化为方向明确的页面进入动画。
3. **稳定框架不重播**：标题栏、侧栏、课程上下文条保持稳定，仅主内容舞台切换；侧栏活动指示器沿导航轨道移动。
4. **局部反馈短而准**：悬停、按压、菜单、工具栏、检查器和通知使用 80–240ms 的局部反馈；模态层和抽屉最多 320ms。
5. **不制造噪声**：不使用无限动画、持续呼吸、大幅缩放、随机漂浮或全屏渐变运动；列表错峰最多前 5 项，总编排窗口不超过约 420ms。
6. **性能优先**：主动画只使用 `transform` 与 `opacity`；必须改变布局的侧栏折叠保持短时并使用 containment；不引入运行时动效依赖。

## 架构

### Motion contract

`frontend/src/ui/motion.ts` 负责路由深度、导航方向、共享元素名称、View Transition 调度与 reduced-motion 检测。所有路由变化统一经过该入口，避免组件各自猜测动画方向。

`frontend/src/components/MotionPresence.tsx` 负责条件 UI 的进入、稳定、退出三个阶段。弹窗、菜单与抽屉在退出动画完成后再卸载，避免当前的瞬间消失。

`frontend/src/styles/motion.css` 是唯一的动效表现层，消费 `tokens.css` 中的时长、距离与曲线变量。现有布局样式不承载新的动效策略。

### 空间层级

- L0：全局课程书架、回收站、全局设置。
- L1：单课程主页。
- L2：课程模块（驾驶舱、路线、知识笔记书架、资料、实验室等）。
- L3：具体知识画布。

由低到高是 `forward`，由高到低是 `back`，同层模块为 `lateral`，跨课程替换为 `replace`。历史返回同样复用该分类。

### 组件行为

- **课程/笔记**：列表只做小距离错峰进入；打开时封面通过共享元素缩放和位移到目标标题区。
- **侧栏**：活动指示器沿纵轴滑动；折叠时先收文字、后收容器，图标保持视觉锚点。
- **知识画布**：工具栏保持稳定；新卡片短距离进入；检查器从右侧贴边出现；资料抽屉从其所属右侧层级进入。
- **弹窗/菜单**：遮罩先显现，表面从触发层上方 8–12px 进入；关闭时反向且更快。
- **反馈**：通知从底部轻推进入；进度条使用统一曲线；按压反馈不造成布局位移。

## 无障碍与降级

`prefers-reduced-motion: reduce` 时禁用 View Transition、共享元素形变、错峰与位移动画，只保留接近瞬时的颜色/可见性更新。焦点环、`aria-current`、对话框语义和键盘 Escape 行为保持不变。

## 测试与验收

- 纯函数测试覆盖路由层级和方向分类、共享名称与 View Transition 降级。
- Presence 测试证明退出阶段保留 DOM 并在时限后卸载。
- 组件测试覆盖侧栏活动指示器、课程与笔记共享元素名称。
- 静态策略测试禁止无限动画，要求 reduced-motion、View Transition 和统一 token。
- 最终运行 Vitest、TypeScript、Vite/Electron production build；条件允许时运行 Playwright 关键流。
