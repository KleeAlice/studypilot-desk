# StudyPilot Desk 设计说明

## 目标与边界

StudyPilot Desk 是本地优先的个人学习操作系统，把学习输入、工程实现、Python 测试、离线评测、失败案例、掌握度、间隔复习、周复盘、项目/研究证据和求职表达连成闭环。P0 必须可运行、可保存、可搜索、可备份；在线 AI、Dense Retrieval、Reranker、多用户和云同步不阻塞首版。

## 方案比较

采用 Electron + React + FastAPI + SQLite：它满足附件硬性约束。桌面生命周期、文件选择与剪贴板位于 Electron；业务、解析、检索、评测和 Python 运行编排位于 Python；React 仅通过类型化 API 使用数据。代价是需要管理两个进程，但边界清晰且易于独立测试。

未采用纯 Electron/Node，因为它不能满足 FastAPI/Python 服务层要求；未采用浏览器前端加本地服务，因为它不能自然满足无边框窗口、系统剪贴板、窗口状态和退出清理要求。

## 架构

- `electron/`：窗口、预加载白名单、文件对话框、后端子进程、关闭清理。
- `frontend/`：React 页面、状态、API 客户端、主题、动效和可访问性。
- `backend/app/`：FastAPI、Pydantic schema、服务、仓储、解析、检索、评测和 Python runner。
- `data/`：SQLite、文档、附件、Python 工作区、实验输出、索引和备份。
- `data/seeds/`：从 DOCX 提取的 24 周路线、阶段门和模板。

前端不直连数据库。所有写操作经 API 校验后进入仓储层，并由服务层维护跨表约束。API 统一返回 `data/meta` 或统一错误对象，生产环境不暴露 traceback。

## 核心数据流

1. 首次启动：Electron 启动本地后端，等待健康检查，打开 React；后端迁移数据库并导入种子路线。
2. 学习执行：路线生成课程和周任务；任务证据关联笔记、代码运行、测验和实验。
3. 文档：文件复制到托管目录，解析正文和元数据，写入 SQLite FTS；高亮可转笔记和知识点。
4. Python：API 写入临时工作区，独立解释器子进程运行；按 token 查询状态或停止，限制时间和输出，结果可保存为任务证据。
5. 掌握度：测验与运行证据更新可解释的 Beta-Binomial 统计；复习调度从弱项和到期日生成。
6. 备份：数据库和托管文件打包为 zip 并写 manifest；恢复前校验版本、路径和归档安全。

## 错误与安全

- 后端仅绑定回环地址，Electron 使用 `contextIsolation` 并禁用 renderer Node 权限。
- 用户路径规范化并限制在允许根目录；导入文件限制类型和大小。
- Python runner 不与 API 同进程，具有超时、停止、输出上限和工作目录隔离；明确披露它不是 OS 级强沙箱。
- 数据库写入用事务；备份恢复先验证再替换，失败保留原数据。
- Electron 退出时先请求后端优雅关闭，超时才终止进程树。

## UI 设计

桌面采用指挥台布局：窄侧栏承载全局导航，顶部自定义标题栏，主区域展示今日执行、周路线和证据流，右侧上下文面板按页面出现。深色使用深蓝黑和电光蓝，浅色使用灰白；青绿表示学习、紫色表示工作流、橙色表示实验、品红表示研究、红色仅表示阻断。

1366×768 保留全部关键按钮，宽屏增加证据侧栏。动画只使用 transform/opacity，常规过渡短于 500ms，并尊重 reduced motion。

## 测试策略

- 后端 pytest：迁移、路线导入、CRUD、DAG、FTS、解析、runner、测验、掌握度、复习、闸门、备份恢复。
- 前端 Vitest/Testing Library：导航、表单、数据刷新、主题和错误状态。
- 桌面：构建后启动 Electron，检查 preload、窗口按钮、后端健康、关闭清理和重复启动。
- 视觉：在 1366×768、1440×900、1920×1080 检查水平溢出、弹窗边界和控制台错误。

## 明确取舍

- 首版用 SQLite FTS5/BM25 完成真实检索；Dense/RRF 是 P1。
- 导图首版实现可编辑节点/连线与持久化，不引入大型画布框架。
- 可选 AI 只提供 provider 配置和可用性检测；无密钥时核心功能正常。
- 不伪造学习指标、实验结果和简历数据；演示数据带 `demo` 标识。
